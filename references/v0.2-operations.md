# V0.2 read-only planning, remote inventory and snapshots

This filename retains a historical milestone label; it is not the project's
current capability inventory. These are Agent/developer helper examples.
See the [capability matrix and validation record](roadmap.md) for current scope.

## Local plan

```bash
python3 scripts/safety/validate_profile.py profiles/base/ubuntu-server.json
python3 scripts/system/plan.py profiles/base/ubuntu-server.json
```

Exit status **3** means the host is not compatible with the profile; do not apply. Exit **2** means invalid inputs. The plan enumerates package and hostname/timezone drift; no changes occur. Package detection uses dpkg-query; Debian-derived distros only.

## Remote inventory

Configure `Host target-alias` in your own `~/.ssh/config` and enroll/verify its SSH host key out-of-band first.

```bash
python3 scripts/remote/ssh_probe.py target-alias
```

This executes hard-coded read-only commands using OpenSSH with strict host-key checking and batch authentication. Remote output may include sensitive infrastructure details. The runner does **not** install keys, upload scripts, enable password login, or modify the host. The remote probe must not be exposed directly to arbitrary untrusted host aliases or untrusted SSH configuration.

## File snapshot

```bash
python3 scripts/safety/snapshot.py --output-dir /tmp/uc-snapshot-001 /etc/hostname
```

The snapshot copies only explicitly specified ordinary files into a new directory with private permissions and writes hashes plus ownership/permissions metadata. It is local only and does not restore anything. Avoid using world-writable or shared backup destinations for sensitive files. Keep long-term backups off the target system.

## Not yet implemented

Profile application, idempotent mutation adapters, automatic reversion,
transactional remote network changes and complete system backup remain
unsupported. These require implementation and separate safety verification.

Image inspection, VM RAW/QCOW2 conversion, limited offline RootFS customization
and optional AMD64 guest-health verification are implemented in separate
helpers; see [image building](image-building.md). Their real image builds and
boots remain unverified. Installer ISO creation, physical IMG/BSP assembly,
installed-system cloning and flashing are still unsupported.
